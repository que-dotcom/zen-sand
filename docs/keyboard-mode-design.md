# 下部バー再編 + キーボード操作 設計書

日付: 2026-08-07 / 状態: PR1 実装済み（下部バー再編）。PR2〜PR4 は未実装

## 背景と目的

サークルの出し物で、自作キーボードから操作して遊べるようにしたい。
同時に、素材が32種まで増えて下部バーが横スクロールなしでは見られなくなっている。

この2つは別々の課題に見えて、実は同じ構造の問題である。

- バーが読めないのは「32個を1次元に並べている」から
- キーボードで選べないのは「1素材＝1キーで32キー消費している」から

どちらも **グループ × 素材の2次元** に組み替えることで同時に解ける。
画面の見た目と操作の構造を一致させるのが本設計の主眼である。

**方針: マウスとキーボードのどちらでも遊べる。モード切替は明示操作ではなく自動。**

## 現状の問題（実測）

| 箇所 | 問題 |

## 1. グループの再編

命名と所属を実態に合わせ直す。8グループ・最大6個に収まるので、
どのグループを選んでもスクロールが発生しない。

| グループ | 素材 | 数 |
|---|---|---|
| 基本 | 砂・水・雪・壁 | 4 |
| 火 | 火・油・溶岩・炭 | 4 |
| 生命 | 土(落)・土(固)・種・菌・酸植物 | 5 |
| 気液 | 蒸気・酸・泥・氷 | 4 |
| 岩石 | 黒曜石・砂岩・玄武岩・水源・溶岩源 | 5 |
| 電気 | 金属・雷・金 | 3 |
| 侘寂 | 桜種・花びら・蛍・花粉・間・鯉 | 6 |
| 道具 | 熊手・消 | 2 |

計33種（2026-08-11 追記: 金継ぎシナリオで金 [n] が電気グループに追加された。
侘寂は6個で満杯のため、伝導する金属つながりで電気に置いた）。移動のみで**素材の挙動・ID・色は一切変えない**（`PALETTE` の `group` 文字列と並び順だけの変更）。

変更点は3つ:
- `'燃焼'`（8個）を `基本`(4) と `火`(4) に割る
- 酸植物を `'岩石'` → `生命` へ移す
- `'ツール'` を `道具` に改名（1文字あたりの幅を揃えるため）

## 2. 下部バーのレイアウト

3行構造にする。全ての行が「左右に並んだ項目の列」という同じ形をしているのが要点で、
これがそのままキーボードの2次元ナビゲーションになる。

```
┌────────────────────────────────────────────────────┐
│  基本   火   生命   気液   岩石   電気   侘寂   道具 │ ← 行0: グループタブ
│  ▔▔▔▔                                              │
│  ●砂    ●水    ●雪    ●壁                          │ ← 行1: 選択中グループの素材（最大6）
├────────────────────────────────────────────────────┤
│  ブラシ ⊖ ③ ⊕    🎬  🧪  ☁  🔔  🍃    クリア       │ ← 行2: 操作
└────────────────────────────────────────────────────┘
```

### DOM構造

```html
<div id="ui">
  <div id="palette">
    <div class="nav-row" id="group-tabs"></div>   <!-- 行0 -->
    <div class="nav-row" id="mat-row"></div>      <!-- 行1 -->
  </div>
  <div class="nav-row" id="controls">             <!-- 行2 -->
    <span class="ui-label">ブラシ</span>
    <button id="brush-dec" class="ctl-btn">⊖</button>
    <span id="brush-val">3</span>
    <button id="brush-inc" class="ctl-btn">⊕</button>
    <button id="scenario-btn" class="ctl-btn">🎬</button>
    <button id="practice-btn" class="ctl-btn">🧪</button>
    <button id="rain-btn"     class="ctl-btn">☁</button>
    <button id="sound-btn"    class="ctl-btn">🔔</button>
    <button id="chiri-btn"    class="ctl-btn">🍃</button>
    <button id="clear-btn"    class="ctl-btn">クリア</button>
  </div>
</div>
```

### ブラシスライダーを ⊖ / ⊕ の2ボタンに置き換える理由

`<input type="range">` はキーボードで扱うと「フォーカスして左右で値変更」となり、
他の行の「左右で項目移動」と操作が衝突する。ボタン2個にすれば
**全ての行で「←→で移動、決定で実行」に統一**できる。現在値は横に数字で出す。

マウス操作でも、スライダーより⊖⊕のほうが1段ずつ確実に変えられて出し物向きである。

### 見やすさのための処理

- グループタブは常時8個すべて表示（横スクロールなし）。選択中は下線＋文字を白に
- 素材ボタンは色ドットを 8px → 12px に拡大し、離れた席からも色で判別できるようにする
- 素材行は最大6個なので、余白を広くとって1つずつを大きくできる
- 行の高さを揃え、行間に薄い区切り線を入れて3行構造を明示する

## 3. キーボード操作の中核設計

### 3-1. 仮想カーソル（新規 `src/cursor.js`）

マウスポインタの代わりに、盤面上を動く照準を持つ。

```js
class Cursor {
  cx, cy          // グリッド座標（小数を保持して滑らかに動かす）
  visible         // 表示中か
  vel             // 現在速度（cells/frame）
}
```

**移動モデル — 押しっぱなしで加速する**

一定速度だと「微調整はできるが画面端まで遠い」か「速いが狙えない」のどちらかになる。
押し始めはゆっくり、押し続けると速くする。

| 定数 | 値 | 根拠 |
|---|---|---|
| `V_MIN` | 0.35 cells/frame | 約21セル/秒。1セル単位の微調整ができる下限 |
| `V_MAX` | 4.0 cells/frame | 約240セル/秒。1920px幅（=480セル）を約2秒で横断 |
| `RAMP` | 30 frames | 0.5秒かけて最高速へ。押し直せば即座に低速へ戻る |

斜め移動は正規化して速くならないようにする（`/√2`）。

**キーリピートに頼らない**

OSのキーリピートは初回遅延が約500msあり、加速カーブが作れない。
`keydown`/`keyup` で押下キーの集合を保持し、**ゲームループ内で毎フレーム位置を更新**する。

**描画（押している間だけ描く）**

決定キーが押されている間、毎フレーム `input.paintGrid(cx, cy)` を呼ぶ。
熊手の `rakeStroke` は前回位置との差分で歯を並べるので、
カーソルが連続的な位置を渡す限りマウスドラッグと同じ砂紋が引ける。

**見た目**

`renderer.render()` の直後に、同じ `ctx` へ重ね描きする
（`putImageData` は毎フレーム全面を上書きするので、カーソルは毎フレーム描き直す）。

- 細い円 = ブラシ半径そのもの。**ブラシサイズが視覚的に分かる**という副次効果がある
- 中心に小さな十字
- 描画中は円を明るくする
- 半透明の白（庭のどの色の上でも見える）

### 3-2. パレットの2次元ナビゲーション

3つの行を上下に移動し、行の中を左右に移動する。テレビのメニューと同じ操作である。

| 操作 | 動き |
|---|---|
| メニュー + ↑ / ↓ | フォーカス行を移動（グループタブ ⇄ 素材 ⇄ 操作） |
| メニュー + ← / → | フォーカス行の中を左右に移動 |
| メニュー + 決定 | 操作行の項目を実行 |

- **グループタブ行**: 左右に動かすと即座にグループが切り替わり、下の素材行が入れ替わる
- **素材行**: 左右に動かすと即座に素材が選択される（決定は不要）
- **操作行**: 左右は移動だけ。決定で実行する

フォーカス中の項目には光る枠を出す。どの行のどこにいるか常に画面で分かる状態にする。

### 3-3. モードの切り替え — 明示操作は要らない

| 出来事 | 結果 |
|---|---|
| マウスを動かした / クリックした | カーソルを隠す。マウス操作 |
| 方向キー・決定キーを押した | カーソルを表示。キーボード操作 |

トグルボタンを置かない。どちらの入力でも即座にそちらへ切り替わるので、
**出し物で「マウスも使いたい」と言われてもそのまま渡せる**。

## 4. 必要キー数（キーボード側の設計に合わせて選ぶ）

キーの本数によって3段階の構成を用意する。どれを選んでも全機能に到達できる。

### 構成A — 6キー（最小）

| キー | 単押し | メニュー同時押し |
|---|---|---|
| ↑ | カーソル上 | フォーカス行を上へ |
| ↓ | カーソル下 | フォーカス行を下へ |
| ← | カーソル左 | 行内を左へ |
| → | カーソル右 | 行内を右へ |
| 決定 | 描く（押している間） | 操作行の項目を実行 |
| メニュー | — | 修飾キー |

6キーで32素材と全機能に届く。ただし素材を変えるたびに
メニューキーを押さえる必要があり、遊んでいる最中の切り替えはやや重い。

### 構成B — 10キー（推奨）

構成Aに、よく使う操作を独立キーとして追加する。
**メニューキーを押さえずに素材を変えられる**ので、出し物で回転が速い。

| 追加キー | 機能 |
|---|---|
| 素材 ← / → | 選択中グループ内で素材を送る・戻す |
| グループ ← / → | グループを送る・戻す |

メニューキーは操作行（実験・雨・音・散・クリア）専用として残る。

### 構成C — 18キー（快適）

構成Bに、8グループへの直接ジャンプキー（8個）を追加する。
「侘寂」へ一発で飛べるので、素材の場所を覚えた人は最速で操作できる。

### 単独キーを足すなら優先順位

出し物で触られる頻度の高い順。キーに余裕があればこの順で独立させる。

1. 🍃 散（見せ場になる。押したがる人が多い）
2. クリア
3. ☁ 雨モード
4. 🔔 音

## 5. 出し物向けの安全策

- **破壊的操作は長押し確定**: クリアと散は、決定キーを1秒押し続けて初めて発動する。
  押している間は進捗リングを表示する。誤爆で他人の庭を消す事故を防ぐ
- **矢印キーのページスクロール抑止**: `preventDefault` を入れる
- **ボタンのフォーカス奪取を防ぐ**: 決定キーがUIボタンを誤発火しないよう、
  操作行のボタンは `tabindex="-1"` にしてブラウザ既定のフォーカスから外す
- **リサイズ時のカーソルクランプ**: 盤面外に出ないよう毎回丸める
- **キーヒント表示**: キーボード操作中はバーの各行に小さくキー名を出す。
  初見の人が説明なしで触れる状態にする

## 7. 実装順序（4段階、各段階で動作確認できる）

1. **PR1: バーの再編** — グループタブ + 素材行 + 操作行。マウス操作のみ。
   既存のキー割り当て（1素材1キー）はそのまま残す。挙動は不変で見た目だけが変わる
2. **PR2: 仮想カーソル + 描画** — 方向キーで動き、決定キーで描ける。
   マウスとの自動切替もここ。この時点で「キーボードだけで砂を置く」が成立する
3. **PR3: メニューナビゲーション** — 行/項目フォーカス、キーヒント表示、
   構成Bの独立キー割り当て。ここでキーボードだけで全機能に到達する
4. **PR4: 出し物向け調整** — 長押し確定、速度定数の実測調整、初見向けの導線

## 8. リスク

- **カーソル速度の感覚** — 数値は計算で置いたが、最終的には実際に動かした感触でしか決まらない。
  PR2で触ってもらって調整する前提にする
- **熊手の砂紋がキーボードで綺麗に引けるか** — `rakeStroke` は前回位置との差分で歯を並べるため、
  カーソルの移動が遅いと歯の間隔が詰まる可能性がある。PR2で実際に引いて確認する
- **同時押しの取りこぼし** — 自作キーボードの実装によってはNキーロールオーバーでない場合がある。
  斜め移動（2キー同時）が効かない機体もあり得るので、PR4で実機確認したい
- **グループ再編で既存シナリオが壊れないか** — 確認済み。`scenarios.js` に `group` / `PALETTE`
  の参照は0件で、素材IDを直接使っている。グループの組み替えは影響しない
