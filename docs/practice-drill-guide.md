# 実験帳（Practice Mode）お題作成要領

2026-08-11 作成。実験帳の開発で実際に踏んだ失敗と、そこから確立した設計原則の記録。
新しいお題を足すとき・舞台を直すときは、この要領に従う。

---

## 0. 実験帳の仕組み（前提知識）

- 本体は `src/practice.js`。**DOM 非依存**の `PracticeMode` クラスと、お題の配列 `DRILLS` だけでできている。
  DOM・音の配線は `main.js` 側がフック（`onBar` / `onSuccess` / `onFinish`）で注入する
- 現在は16題: 野火、油田の雷鳴、湯けむり、溶岩流、雷とガラス、砂の炉、火口、泥田、
  夜光洞、畑、墨田の夜、凍る池、雷鳴の池、錆の海、蛍の沢、金継ぎ。
- お題 = `{ id, title, goal, products, hint, done, setup(engine) }` の1オブジェクト
- 進行: 🧪で開始 → `setup` が盤面を作る → プレイヤーが素材を注ぐ →
  **生成物のセル数がベースライン（お題開始時）から `goal` 以上増えたら成功** →
  ⭕表示+おりん → **「次へ ➜」を押すまで反応を継続して眺める** → 全題で「皆伝」
- お題の途中は⏭でスキップできる。成功後は同じ場所が「次へ ➜」へ変わり、自動遷移はしない。
- 判定は毎フレーム盤面を数えるだけ。**素材コードには一切依存しない**汎用方式。
  お題を足すのに素材側の変更は原則不要
- 操作: 実験中に🧪でスキップ、クリアボタンで退出。シナリオとは相互排他

## 1. これまでの経緯（何を作り、何を学んだか）

| 版 | コミット | 内容 | 学び |
|---|---|---|---|
| v1 | `a3ab2cf` | 壁の受け皿に液体を入れた10題 | 動くが「実験器具」感。情景に乏しい |
| v2 | `84c0611` | 情景化（草原・山肌・カルデラ…）+ 黒曜石の化学見直し | 黒曜石が世界に定着しない非対称を発見・修正 |
| v3 | `b239053` | 画面全体化 + 固定素材（氷）の廃止 + 雪の化学追加 | 石の蓋・氷の栓という2つの構造的な罠を発見 |

ユーザフィードバックの要点（そのまま設計原則になった）:
1. 「空中に浮いた小さなフィールドは見づらい」→ **舞台は画面全体**
2. 「固定される素材を置かせる反応は避ける。配置が難しく、反応しているのに
   判定されない感になる」→ **プレイヤーが置くのは落ちる・流れる素材だけ**
3. 「化学反応が分かりやすいものを」→ **見て分かる反応だけを採用し、
   分かりにくい原因が素材側にあるなら素材の化学を直す**

## 2. お題の選定基準

1. **反応が「見て分かる」**: 生成物の色が舞台の地形とはっきり区別できること。
   （例: 灰色の山に黒い黒曜石の蓋 ○ / 泥の中に泥色の何か ×。
   v2で「墨」を落として「凍る池」に差し替えたのはこの基準）
2. **既存の化学で自然に起きる**こと。新しい反応則が必要なら、まず素材側を直して
   単体でデバッグ観察してから、お題にする（§5の黒曜石の例を参照）
3. **プレイヤーが置く素材は「落ちる・流れる」ものだけ**:
   砂・水・雪・火・油・溶岩・炭・種・桜種・酸・泥・雷・金・金属。
   **氷・壁・石などの固定素材は禁止**（クリックした空中に貼り付き、
   狙った場所に置けず、「反応しているのに判定されない」体験になる）
4. **数秒の正しい操作で成功に届く**こと（目安は §4）

## 3. 舞台設計の原則

- **画面全体に**: 地形は画面の底から積み上げ、幅いっぱいに広げる。空中の島を作らない
- **枠は張らない**: 画面端が壁の役割をする（`engine.get` は盤外を 255 = 固体として返す）。
  液体を留めたいときだけ、地形自体でくぼみを作る
- **寸法は W/H 比例 + 最小値ガード**: 検証盤面（200×140）と実ゲーム盤面
  （おおよそ 350×220、ウィンドウ依存）の両方で成立させる。
  例: `Math.max(14, Math.floor(H * 0.10))`
- **水面・溶岩面は地表と同じ高さに**: 岸の石を水面より1行でも高く張ると「**石の蓋**」になり、
  上から降らせた素材が水に届かない（v3で池系3舞台がこれで全滅していた）
- **溶岩に接する地形は、溶岩耐性のある静的素材だけ**: `STONE` / `WALL` / `HARD_SOIL` / `GLASS`。
  `BASALT`（2%/frame）と `OBSIDIAN`（0.3%/frame）は溶岩で再溶融するため、
  溶岩を湛える地形に使うと**山が自分の溶岩湖に食われて崩壊**する（v2の火口で実際に起きた）
- **深い穴 × 溶岩 × 雪/氷 は禁止**: 融け水が穴に溜まり、凍結で「**氷の栓**」ができて
  溶岩が密封される。溶岩湖は開けた場所に置き、**縁は溶岩面と同じ高さ**にして
  融け水が流れ落ちる構造にする（v3の火口を台形の楯状火山にした理由）
- **生成物を定着させたいなら溶岩は有限に**: 溶岩源泉があると、できた黒曜石が
  下から再溶融し続けて goal に到達しない。逆に「流れ続ける溶岩」を見せたい
  溶岩流のお題では源泉が主役（生成物が石=再溶融しないので成立する）
- **素材は置いた後も勝手に動く前提で組む**: 雪は水・溶岩の上で即融ける /
  SOIL は粉体として崩れる（畝は三角に積めば安息角で安定）/ 金属は水中で滑り崩れる /
  植物は成長する / 溶岩は横に滑り落ちる。60フレーム流した後の姿が本当の初期状態

## 4. 判定設計

- `products` は数える生成物IDの配列、`goal` はベースラインからの増分
- 複数手順のお題は `instructions` を使う。中間生成物が目標に達したら、次に置く素材と
  場所をバーに表示する（墨田の夜: 炭田へ水 → できた墨泥へ種）。
- 判定は**毎フレームの瞬間値**。消えていく生成物（FIRE・STEAM・SPARK）は
  「同時存在数が goal を超える瞬間があるか」で考える
- goal の目安（機械プレイの実測で、正答プレイ 120〜450 フレーム = 2〜7秒に収める）:
  - 永続する生成物（STONE・GLASS・OBSIDIAN・BASALT・ICE・KINTSUGI）: 8〜12
  - 短命な生成物（FIRE・STEAM・SPARK）: 8〜15
  - 成長する生成物（PLANT・FLOWER）: 3
- 舞台の地形に生成物と同じ素材を使わない（増分判定なので数字上は動くが、
  どこが新しくできたのか見えなくなる。火口の山体を STONE にして
  生成物を OBSIDIAN にしたのはこのため）

## 5. 落とし穴カタログ（すべて実際に踏んだもの）

| 罠 | 症状 | 原因 | 対策 |
|---|---|---|---|
| 石の蓋 | 雪も雷も水に届かない | 岸の地面を水面より1行高く張った | 地表と水面を同じ高さに |
| 氷の栓 | 火口が成功したり詰まったり | 深い穴に融け水が溜まり凍結で密封 | 穴をやめ開けた溶岩湖+縁を溶岩面と同じ高さに |
| 山体の崩壊 | 溶岩が数百セルに増殖し山が消える | BASALT/OBSIDIAN は溶岩で再溶融する | 溶岩周りの地形は STONE/WALL/HARD_SOIL/GLASS |
| 定着しない生成物 | 黒曜石が0〜3個を行き来 | 溶岩源泉の無限供給で再溶融が続く | 生成物を溜めるお題では溶岩を有限に |
| 固定素材のお題 | 氷が空中に貼り付き反応しない | 固定素材は落ちない | 置かせるのは落ちる・流れる素材だけ |
| 生成物の上書き | 蒸気を自分の火で消してしまう | 同一点に置き続ける | ブラシで掃くように塗る（ボットも sweep 方式で模倣） |
| 反応が遅すぎて見えない | 雪を降らせても池が凍らない | 凍結 0.3%/frame は融解に負ける | 素材側の化学を直す（1%に修正済み） |
| 石の皮が先に張る | 急冷したのに黒曜石ができない | 融け水+溶岩→石が先行 | 氷・雪の融解時に接触溶岩を黒曜石化（修正済み） |

補足（素材側に施した修正、再修正しないこと）:
- `updateIce` / `updateSnow`: 融ける瞬間に接触溶岩を OBSIDIAN に急冷
- `updateObsidian`: 溶岩接触の再溶融 3% → 0.3%/frame
- `updateWater`: 雪・氷隣接の凍結 0.3% → 1%/frame

## 6. お題の追加手順（チェックリスト）

1. `src/practice.js` の `DRILLS` に1項目追加（§2〜4 の基準で）
2. `tests/practice.test.mjs` の `ANSWERS` に正答ボットを1行追加
   （sweep 方式 = x をずらしながら置く。§5「生成物の上書き」参照）
3. リポジトリ直下に一時 `package.json`（`{"type":"module"}`）を置いて
   `node tests/practice.test.mjs`
   - **2回連続で全題完走**を確認（1回だと確率揺らぎの不安定を見逃す。
     v3の火口は1回目成功→2回目STALLだった）
   - `tests/out/stage-*.png` を目視（60フレーム流した後の舞台 = 本当の初期状態）
   - 不安定なお題は単体デバッグ: 素材数の推移を200フレームごとに出力し、
     最後に盤面の断面を文字で描くと原因が一目で分かる（氷の栓はこれで発見した）
4. 回帰: `node tests/scenario.test.mjs`（金継ぎの化学とシナリオ2本、20項目）
5. ブラウザ実機: `python -m http.server 8080`。
   **モジュールキャッシュに注意** — 編集ファイルを `fetch(url, {cache:'reload'})`
   してから `location.reload()`（タブが hidden だと rAF が止まる点も注意）
6. 一時 `package.json` を**削除してから**コミット → **push**（どこからでも参照できる運用）

## 7. 文体

- `hint`: 情景 + 素材名 + キー表記 `[x]`。「〜しよう」で終える。
  例: 「火口に、雪 [3] を降らせよう」
- `done`: 短い詩的な一文。例: 「火口は、漆黒の鏡石で蓋をされた」
- `title` は反応名ではなく**情景の名前**: 「野火」「湯けむり」「凍る池」「雷鳴の池」
